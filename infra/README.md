# Benefura infrastructure

azd + Bicep for the live demo. Everything runs in **East US 2** except Azure AI Search. Search reuses an existing Free
service if the subscription has one. Otherwise it creates a Free service in **Canada Central**, because East US 2
currently refuses new search services. Every call is keyless: Entra ID with managed identities and role assignments by
GUID.

```
infra/
  main.bicep                 subscription scope: rg-<env>, modules, azd outputs
  main.parameters.json       azd parameter mapping (${ENV_VAR=default})
  bicepconfig.json           linter rules (secrets/unused params/hardcoded URLs are errors)
  params/demo.bicepparam                 compile check of the demo variant
  params/private-networking.bicepparam   compile/what-if check with enablePrivateNetworking=true
  modules/
    foundry.bicep            AIServices S0 (local auth off) + project + deployments + project connections
    guardrail.bicep          raiPolicy on Microsoft.DefaultV2 (attached to chat deployments)
    aca.bicep                Container Apps environment (Consumption) + API container app
    identity.bicep           user-assigned managed identity for the API
    swa.bicep                Static Web Apps Free
    search.bicep             AI Search Free (created only when not reusing one)
    storage.bicep            StorageV2 (shared keys off) + table `budgets`
    monitoring.bicep         Log Analytics + App Insights + workbook + alerts + action group
    workbook/benefura.workbook.json   generated by infra/scripts/gen_workbook.py
    budget.bicep             Consumption budget on the resource group
    roles.bicep              role assignments in the main resource group
    search-roles.bicep       role assignments on the search service (may be in another resource group)
    role-ids.bicep           built-in role GUIDs (exported)
    network.bicep            optional VNet, private endpoints, private DNS
```

## Outputs and environment contract

(`.github/scripts/export-azd-outputs.sh`). The container app receives the matching env vars, and pydantic-settings maps
`UPPER_SNAKE` names to the `apps/api/app/config.py` fields.

Other container app env vars: `AI_MODE=live`, `SEARCH_INDEX=public-knowledge-v1`, `BUDGET_TABLE=budgets`,
`AGENT_VERSIONS` (JSON object), `DAILY_BUDGET_USD_EXTRACTION|CHAT|EVALS`, `OTEL_SERVICE_NAME=benefura-api` and
`EVALS_SHARED_SECRET` (a Container Apps secret, set only when the GitHub secret exists).

Notes for the API:
- `CORS_ORIGINS` is set as a **JSON array** (`["https://swa-….azurestaticapps.net"]`). pydantic-settings JSON-decodes
  `list[str]` fields from the environment before validators run, so a comma-separated value raises `SettingsError`
  (checked locally).
- `AGENT_VERSIONS` is a JSON object. Bicep takes it as `name=version` pairs (`AGENT_VERSIONS` in the azd env), so the
  azd parameter file never has to embed JSON.
- In GitHub Actions `AZURE_CLIENT_ID` means the CI app registration. The export script therefore publishes the API
  identity only as `API_IDENTITY_CLIENT_ID`.

## How the GHCR image gets deployed (no ACR)

The API image lives in **GitHub Container Registry (public)**. That saves the ACR cost and the AcrPull role.

1. `deploy.yml` builds `apps/api/Dockerfile` (build context `apps/api`) and pushes
   `ghcr.io/<owner>/benefura-api:sha-<commit>` and `:latest` with `GITHUB_TOKEN` (`packages: write`).
2. The job sets `API_IMAGE` in the azd env **before** `azd provision`, so the container app template already points at
   the new image. The app needs no registry credentials because the package is public. After the first push, set the
   package to *Public* once in GitHub → Packages → benefura-api → Settings.
3. After agents are published, `az containerapp update --image $API_IMAGE --set-env-vars AGENT_VERSIONS=<json>` pins the
   image and agent versions in one revision.
4. `azure.yaml` declares `api` with `host: containerapp` and `image: ${API_IMAGE}`. azd forbids `project` together with
   `image`, so the source path lives in the workflow. With no `AZURE_CONTAINER_REGISTRY_ENDPOINT` output and no
   `docker.registry`, `azd deploy api` (or `azd up` locally) swaps the container app's image to `${API_IMAGE}` as is:
   no build, no pull or retag, no ACR.

Before provisioning, the previous `AGENT_VERSIONS` is read from the running container app and passed back in. A
re-provision therefore never produces a revision without pinned agents.

## Deployment flow

Local (first time):

```sh
azd auth login
azd env new benefura-demo --location eastus2
azd env set API_IMAGE ghcr.io/<owner>/benefura-api:latest     # required
azd env set ALERT_EMAIL you@example.com                       # optional: alerts + cost budget
bash spikes/s09_search_free.sh                                # finds an existing Free search service
azd env set AZURE_EXISTING_SEARCH_SERVICE_NAME <name>         # only if one exists
azd env set AZURE_EXISTING_SEARCH_RESOURCE_GROUP <rg>
azd up
azd pipeline config                                           # GitHub OIDC app + repo variables
```

GitHub (`.github/workflows/deploy.yml`, push to `main` or manual):
GHCR image → `azd provision --no-prompt` (the postprovision hook runs `setup_cu.py`) →
`python -m app.agents.publish` (last stdout line = `{agent: version}` JSON) → `az containerapp update` (image +
`AGENT_VERSIONS`) → `azd deploy web` (the prepackage hook builds with `NEXT_PUBLIC_API_BASE_URL=$API_URL` and writes
`staticwebapp.config.json`) → `.github/scripts/smoke-test.sh`.

Smoke tests (M1 pass criteria):
- `GET /healthz` returns 200 with `ok: true`, retrying through a cold start.
- CORS from the SWA origin: the actual response exposes `x-benefura-trace-id`, the `POST /api/chat` preflight is allowed
  and a foreign origin is refused. Starlette sends `Access-Control-Expose-Headers` on actual responses, not on preflights.
- The SWA site returns the CSP with `connect-src 'self' <api origin>`, plus `nosniff` and `no-referrer`.
- The smoke request's trace (sent with a W3C `traceparent`, or the returned `x-benefura-trace-id`) appears in App
  Insights. The check retries for up to 10 minutes.

Other workflows:
- `ci.yml`: API (ruff, format, pyright, pytest, openapi drift); web (gen:check, typecheck, lint, vitest, build, Playwright
  with the fake API); `knowledge/`, `evals/` and `samples/` pytest when their `pyproject.toml` exists; Bicep build and
  lint for every file with warnings treated as failures; both `.bicepparam` variants; workbook drift; SWA config
  generator.
- `knowledge-ingest.yml` (weekly + manual): runs `azd env refresh`, then `uv run --project knowledge python -m knowledge.ingest`.
  The report goes to `INGEST_REPORT_PATH` and then to the job summary.
- `evals.yml` (weekly + manual): runs `evals.harness`, `evals.cloud_evals`, `evals.red_team` and `evals.gate` (reads
  `evals/thresholds.yaml`). It uploads reports and opens a PR with `evals/reports/**` and `docs/evals/**`. The job fails
  when the gate fails, after the PR is opened.

## Telemetry contract (workbook and alerts depend on it)

OpenTelemetry metrics exported by `azure-monitor-opentelemetry` land in App Insights `customMetrics`:
- `name` is the instrument name.
- Counters are delta sums in `valueSum`.
- Histograms carry `valueSum`, `valueCount`, `valueMin` and `valueMax`.
- Attributes land in `customDimensions`.

Attribute values are categories and counts only: never user text, PII values or alias maps.

| Instrument | Type | Unit | Attributes | `app/telemetry.py` function |
|---|---|---|---|---|
| `benefura.model.tokens` | Counter | `{token}` | `benefura.agent`, `benefura.model`, `benefura.token_type` = `input` \| `output` | `record_model_usage` |
| `benefura.model.duration` | Histogram | `ms` | `benefura.agent`, `benefura.model` | `record_model_usage` |
| `benefura.step.duration` | Histogram | `ms` | `benefura.step` | `record_step_latency`; also `record_router_decision` (`router`), `record_search` (`search`), `record_model_usage` (`model`) |
| `benefura.router.decisions` | Counter | `{decision}` | `benefura.route` = `plan_claims` \| `knowledge` \| `off_topic` | `record_router_decision` |
| `benefura.tool.calls` | Counter | `{call}` | `benefura.tool`, `benefura.executor` = `server` \| `browser`, `benefura.outcome` = `ok` \| `error` \| `rejected` \| `declined`, `benefura.error` (code or `none`) | `record_tool_call` |
| `benefura.tool.duration` | Histogram | `ms` | `benefura.tool`, `benefura.executor` | `record_tool_call` |
| `benefura.safety.events` | Counter | `{event}` | `benefura.safety_kind` = `content_filter` \| `jailbreak` \| `indirect_attack` \| `prompt_shield_document` \| `unsafe_image` \| `pii_blocked`; `benefura.surface` = `chat` \| `booklet` \| `receipt` \| `knowledge` | `record_safety_event` (and hard-tier `record_pii_hits`) |
| `benefura.pii.hits` | Counter | `{hit}` | `benefura.pii_category`, `benefura.pii_tier` = `hard` \| `advisory`, `benefura.surface` | `record_pii_hits` |
| `benefura.search.queries` | Counter | `{query}` | `benefura.zero_results` = `true` \| `false` | `record_search` |
| `benefura.search.duration` | Histogram | `ms` | — | `record_search` |
| `benefura.search.top_score` | Histogram | `1` | — | `record_search` (skip when `None`) |
| `benefura.verifier.verdicts` | Counter | `{row}` | `benefura.verdict` = `supported` \| `corrected` \| `unsupported` | booklet workflow |
| `benefura.budget.spend_usd` | Counter | `USD` | `benefura.namespace` = `demo-extraction` \| `demo-chat` \| `evals` | `record_budget_spend` |

## Private networking (`enablePrivateNetworking=true`)

What the flag turns on:
- A VNet with a delegated Container Apps subnet (/23) and a private endpoint subnet.
- Private endpoints for the AIServices account (`account`) and the Storage table (`table`).
- Private DNS zones: `privatelink.cognitiveservices.azure.com`, `privatelink.openai.azure.com`,
  `privatelink.services.ai.azure.com` and `privatelink.table.core.windows.net`.
- `publicNetworkAccess: Disabled` on the account and storage.
- The Container Apps environment joins the VNet; its ingress stays external for the browser.

CI compiles this variant with `az bicep build-params` on `params/private-networking.bicepparam`. `deploy.yml` can run a
subscription `what-if` for it (manual input).

Not covered (see the ADR):
- AI Search Free and SWA Free have no private endpoints.
- Prompt agents that call into the VNet need Foundry agent network injection.
- GitHub-hosted runners can't publish agents or run `setup_cu.py` against a private account. Use a self-hosted runner
  in the VNet.
- App Insights ingestion stays public; AMPLS is out of scope.
